# 測試與驗收計畫

## 1. 測試環境紀錄

每次測試至少記錄：

- 韌體 commit
- XIAO／Sense 板版
- 相機型號
- microSD 品牌、容量與格式
- 電池型號與當下電壓
- 手機型號、OS、瀏覽器
- 測試日期

## 2. 核心功能

| ID | 測試 | 通過條件 |
|---|---|---|
| F-01 | 冷開機 | 10 次皆進入預覽，不卡開機 |
| F-02 | 短按快門 | 每次只觸發一張 |
| F-03 | 拍後回看 | 2 秒內顯示且方向正確 |
| F-04 | 隨機成功文字 | 五句皆能出現、同句不連續重複，且明暗照片上可讀 |
| F-05 | 寫入原圖 | JPEG 可在電腦與手機開啟 |
| F-06 | JSON 配對 | 每張照片有同 ID metadata |
| F-07 | 重新開機 | 舊照片仍可讀且序號不重複 |
| F-08 | 電量提示 | 分段與實測電壓相符 |
| F-09 | USB 充電 | 充電狀態正確，無異常發熱 |

## 3. 錯誤與復原

| ID | 情境 | 預期 |
|---|---|---|
| E-01 | 未插 SD 開機 | 顯示插卡提示，不假裝拍成功 |
| E-02 | SD 滿 | 阻止拍照、提示清理／換卡 |
| E-03 | 儲存時斷電 | 正式檔不半毀；temp 可清理 |
| E-04 | 相機初始化失敗 | 顯示錯誤碼，可重試 |
| E-05 | Wi‑Fi 連線中斷 | 相機核心拍照仍可用 |
| E-06 | 低電量拍照 | 安全保存或先阻止，不反覆重啟 |
| E-07 | 網頁請求不存在照片 | 404 JSON，不當機 |
| E-08 | 錯誤管理 PIN | 不刪除，有限速 |

## 4. 壓力測試

### S-01：30 張硬體 Gate

流程：預覽→拍照→存 SD→TFT 回看，重複 30 次。

通過：

- 30 張都存在。
- 可讀率 100%。
- 無花屏、SD unmount、watchdog 或 brownout。

### S-02：100 張展示耐久

模擬真實節奏連拍 100 張。

通過：

- 成功率至少 98%。
- 失敗能恢復，不需整機斷電。
- 檔名不重複。

### S-03：下載壓力

- 手機連續瀏覽／下載 20 張。
- 第二台手機同時開首頁。

通過：不重啟、不造成新拍照檔案損壞；必要時第二個下載回 429／忙碌提示。

### S-04：拍照回饋狀態切換

預覽→拍照→原子寫入 JPEG／JSON→顯示照片與隨機文字→返回預覽，重複 30 次；另模擬一次儲存失敗。

通過：無 brownout、花屏或卡死；成功時顯示五句之一，失敗時只顯示錯誤而不顯示成功文字。

## 5. 手機網站相容性

最低矩陣：

| 平台 | 瀏覽器 | 必測 |
|---|---|---|
| iPhone | Safari | Captive Portal、相簿、下載 |
| Android | Chrome | Captive Portal、相簿、下載 |
| Windows／macOS | Chrome | 備援網址、管理頁 |

每台測：

- 連線無網際網路時是否仍保持 Wi‑Fi。
- Captive Portal 是否自動出現。
- `tigercam.local` 是否解析。
- 備援 IP 是否可用。
- 原圖方向。
- 四個濾鏡。
- 日期時區。
- JPEG 下載後是否進入檔案／照片 App。
- 重新載入不會重做或丟失使用者選擇。

## 6. 後製視覺測試

準備至少六張基準圖：

- 白天人像
- 室內暖光
- 低光
- 高對比逆光
- 橫向
- 直向

逐效果檢查：

- 膚色沒有不可接受偏色。
- 日期不被裁切。
- 邊框與圖案位置隨長寬比正確。
- 顆粒不是固定貼圖重複得過於明顯。
- 輸出尺寸與 JPEG 品質符合設定。

## 7. 外殼測試

- 10 次拆裝後螺絲柱不裂。
- 從桌面手持高度意外滑落的風險評估；原型不宣稱耐摔。
- 按快門不使鏡頭明顯位移。
- 螢幕在正常視角可見，嘴框不裁關鍵 UI。
- 五句文字在虎嘴遮罩內都完整可讀。
- 天線前方無金屬阻擋。
- USB-C 線材可插到位。
- 電池無擠壓、折線、螺絲穿刺風險。
