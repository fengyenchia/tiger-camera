# Tiger Camera V1 完整產品規劃

## 1. 產品定義

Tiger Camera 是專案暫名；成本版 V1 改成基本矩形相機外殼，不製作虎頭、虎嘴或其他角色結構。拍照成功後，小型彩色螢幕只顯示最新照片，不顯示隨機文字。最新 JPEG 只暫存在裝置 PSRAM，下一次成功拍攝時直接取代；正式復古後製交由手機瀏覽器處理，雲端原圖只供領取與後製暫用，公開相簿永久保存完成圖。

一句話版本：

> 按下相機快門，螢幕立即回看並在私人草稿上傳後顯示領取碼；使用者掃 NFC，在自己的手機後製、下載完成圖或選擇公開。

## 2. 設計目標

1. **先省硬體成本**：使用基本外殼與單純拍後回看，不加入角色結構、音效或螢幕隨機文字。
2. **可完成**：ESP32 只做擅長的拍攝、儲存、顯示與區域傳輸；複雜後製放到手機。
3. **離線核心可用**：沒有網際網路時仍能拍照與回看最新照片；領取、下載、公開相簿與管理操作需要網際網路。
4. **原圖只做暫存來源**：瀏覽器後製期間不修改原始 Blob；公開成功或草稿逾期後刪除雲端原圖。
5. **私人領取、選擇公開**：裝置先上傳私人原圖；領取者可發布完成圖，所有人可查看公開完成圖，只有管理員能永久刪除任意公開照片。
6. **先證明核心技術，再做漂亮外殼**。

## 3. 主要使用者流程

### 3.1 拍照

1. 長按電源或喚醒按鍵啟動。
2. 小型螢幕顯示即時預覽。
3. 使用者短按實體快門。
4. 裝置鎖定畫面並拍攝 JPEG。
5. 將相機 framebuffer 複製到裝置持有的 PSRAM buffer，再歸還相機 framebuffer。
6. 複製成功後，螢幕顯示剛拍的照片 3～5 秒，不疊加隨機文字。
7. 回到即時預覽。

目標體感：

- 從按下快門到畫面凍結：小於 300 ms。
- 從按下快門到可看到成品預覽：小於 2 秒。
- buffer 配置或複製失敗時不得假裝成功，必須顯示明確提示。
- 拍攝或複製失敗時顯示明確錯誤訊息；成功時只回看照片。

### 3.2 手機取圖與後製

1. 相機連接預先設定的 2.4 GHz 手機熱點或可信任 Wi-Fi。
   只有相機需要連上這個熱點；領取者使用自己的行動網路或一般 Wi-Fi 開啟網站，不必加入相機所在的熱點。
2. 拍照後先上傳原始 JPEG 為私人草稿；上傳完成前螢幕顯示「上傳中」或「等待網路」。
3. Server 確認原圖完整後回傳 6 位、24 小時有效的配對碼，相機螢幕顯示該碼。
4. 使用者以自己的手機掃描機身 NTAG213／NTAG215，開啟 `https://tiger-camera.fengyenchia.com/create`。
5. 使用者輸入螢幕領取碼，Server 直接查詢明碼；第一次成功領取後清除配對碼並換發單張照片 opaque UUID token。
6. 網站以 claim token 讀取私人原圖；使用者在自己的手機開關拍立得框、拍攝時間、文字及復古濾鏡，或全部不選。拍攝時間由照片資料自動帶入，不提供手動日期選擇。
7. 文字可使用自訂內容、系統預設文字或完全不顯示。
8. 使用者可下載完成 JPEG；下載不需要管理員帳號，也不會自動公開。原圖不提供下載。

### 3.3 永久保存與管理

1. hosted site 只在目前頁面的記憶體保留領取者取得的原始 JPEG Blob，並產生完成 JPEG Blob。
2. 使用者決定只下載，或勾選「公開到網站相簿」；預設不公開。
3. 有效 claim token 可為同一張草稿取得 processed object 的短效上傳網址，不需要管理員 JWT，也不能操作其他照片。
4. 勾選公開後，後製 Blob 與設定先進入 hosted site 的 IndexedDB 待傳佇列。
5. 瀏覽器上傳後製圖，再呼叫 publish API。
6. Server 確認完成圖與 metadata 完整後，才把草稿改為 `active` 並顯示「已公開」。
7. 發布成功後刪除 R2 私人原圖；若刪除暫時失敗，由 cleanup cron 重試，公開 API 永遠只提供完成圖。
8. 相簿按一次刪除後直接永久刪除完成圖與 metadata；V1 不設垃圾桶、還原或確認視窗。
9. 上傳失敗時保留待傳狀態，提供重試與下載到手機；不得假裝已保存。

### 3.4 網址與憑證的正確定位

- NFC 固定寫入 `https://tiger-camera.fengyenchia.com/create`，不隨照片改寫，也不保存領取碼。
- `https://tiger-camera.fengyenchia.com/gallery` 是所有人可瀏覽的公開相簿。
- ESP32 只保存可撤銷、限定建立私人草稿的 device credential，不保存管理員 JWT、R2 或 Neon 密鑰。
- 領取碼只是方便找到照片的配對碼，不是安全密碼；驗證成功後改用資料庫保存的單張照片 UUID Bearer token。
- 管理員 JWT 只用於刪除、草稿清理與裝置管理，不交給領取者或 ESP32。

## 4. 功能範圍

### 4.1 V1 必做

- 即時相機預覽
- 單一實體快門短按拍照
- 最新 JPEG 複製並暫存在 PSRAM
- 拍後回看
- 拍後只回看剛拍的照片，不顯示隨機文字
- 1.44 吋 128 × 128 或 1.8 吋 128 × 160 ST7735 SPI 螢幕
- Wi-Fi station 連接手機熱點／可信任 Wi-Fi、自動重連與上傳重試
- device-scoped 私人草稿上傳、短效領取碼與螢幕狀態
- 指向正式網站 `/create` 的 NFC 固定網址
- 可獨立開關的拍立得框、時間戳記、文字與手機端復古濾鏡
- 自訂文字、預設文字或無文字；四項後製內容允許全部不選
- 完成 JPEG 下載；原圖不提供下載
- `tiger-camera.fengyenchia.com` 領取碼流程與管理員登入
- 私人 R2 bucket 暫存原圖並保存完成圖；公開 API 只讀完成圖
- 照片 metadata、相簿列表與單次操作直接永久刪除
- 短效限定路徑上傳網址；長期儲存密鑰只留在伺服器
- hosted site 後製圖待傳／重試狀態與未領取草稿逾時清理
- USB 供電；電池版另以實測確認充電、保護與穩定 5 V 升壓
- 電池版的充電狀態提示；不承諾未量測的百分比電量
- 基本矩形 3D 列印相機外殼
- 錯誤狀態：尚無照片、記憶體不足、拍攝失敗、低電量

### 4.2 V1 明確不做

- GIF 或影片
- 觸控螢幕
- Bluetooth 傳照片
- 專屬手機 App
- 公開註冊與多使用者帳號
- AI 濾鏡
- 相機端高解析度後製
- 自動上傳社群
- 多台相機互傳
- microSD 裝置端永久保存、裝置端 JSON metadata 與裝置端多照片相簿

### 4.3 待做清單

- 長按快門進行 2～3 秒動態連拍
- 手機端合成與下載 GIF
- 更多濾鏡與手動參數
- microSD 裝置端離線備份與 JSON metadata
- OTA 無線更新
- 更完整的休眠與喚醒
- 多使用者帳號與分享權限

## 5. V1 後製內容

四項內容可獨立開關，也允許全部不選：拍立得框、拍攝時間、文字與復古濾鏡。拍攝時間自動取自照片 metadata；使用者只決定是否顯示。文字可選自訂、預設或無文字。

復古濾鏡 preset：

| 濾鏡 | 視覺配方 |
|---|---|
| Tiger Film | 暖橘、低對比、輕暗角、細顆粒 |
| Jungle Green | 綠黃偏色、降飽和、柔和高光 |
| Baby Tiger | 明亮暖色、柔和對比、淡粉橘色調 |
| Night Hunter | 黑白或低飽和、高對比、粗顆粒、強暗角 |

拍立得框、時間戳記與文字不綁定濾鏡；例如可以只選 Tiger Film、不加框與文字，也可以只加自訂文字、不使用任何濾鏡。

輸出原則：

- 長邊最多維持原圖解析度，不無意義放大。
- JPEG 品質預設 0.9，可切換「高畫質」0.95。
- 後製結果不回寫相機或 microSD；可下載到手機，領取者也可選擇上傳後製圖並公開。

## 6. 資料、保存與隱私

V1 預設是「私人草稿＋持碼領取」：

- 原圖上傳後只是短期私人草稿，不出現在公開相簿；發布成功或草稿逾期後刪除。
- 6 位英數配對碼以明碼保存、UNIQUE、24 小時有效，成功領取後清除；V1 不做 HMAC 或猜碼 rate limit。
- 領取成功後換發 opaque UUID Bearer token；Server 以資料庫 lookup 確認 token 只能讀取、後製及發布該張照片。
- 猜中別人的配對碼可能先領走照片，這是已接受的 V1 產品取捨；管理員刪除權限不受影響。
- 未領取草稿例如 24 小時後自動刪除；實際期限在測試後鎖定。
- NFC 只保存 `/create` 固定網址，不保存照片、熱點密碼、領取碼或 token。

雲端相簿採不同安全邊界：

- 所有人都能列出及讀取 `active` 照片；領取者只能發布自己持有 claim token 的照片，只有管理員能永久刪除任意照片。
- 管理員短效 JWT 存在 localStorage，前端呼叫受保護 API 時主動帶上 `Authorization: Bearer` header。
- 暫存原圖與完成圖使用不同物件路徑；完成圖不得被後續拍攝覆寫。
- 瀏覽器與韌體不得持有資料庫密碼或長期物件儲存密鑰。
- 照片依序為 `uploading`、`ready`、`claimed`，只有領取者明確發布後才成為 `active`；刪除時改為 `deleting`。
- 發布流程必須移除暫存原圖；管理員永久刪除則移除完成圖與 metadata。部分失敗時保留可重試狀態，不留下無法追蹤的孤兒檔案。

## 7. 成功指標

### 功能驗收

- 連續拍 30 張，最新 buffer 每次都能被正確取代並讀取。
- 重新開機後清楚顯示尚無照片，不宣稱永久保存。
- Android Chrome、iPhone Safari、桌面 Chrome 均可用領取碼取得私人照片並下載完成圖。
- 四款濾鏡及各獨立後製選項的輸出方向、時間、文字與顏色正確。
- 尚無照片、記憶體不足、相機錯誤與低電量都有可理解提示。
- 測試 JPEG 能完成「私人上傳→領取碼→手機後製→可選公開→單次永久刪除」。
- 沒有有效 UUID token 者不能呼叫草稿 API；token 不能操作其他照片或永久刪除。
- 熱點中斷不會顯示領取碼；恢復網路後裝置可安全重試同一張原圖。

### 體驗驗收

- 第一次使用者在沒有口頭教學時，1 分鐘內完成「掃 NFC→輸入領取碼→後製→下載」。
- 拍照成功後只顯示照片，畫面沒有隨機文字或音效。
- 手持時不遮鏡頭、天線與實際 USB 接口。

## 9. 目前尚未鎖死的決策

以下必須由實測決定，不在紙上假定：

1. OTG 與 TTL 兩個 USB-C 在目標 PlatformIO 環境的燒錄與序列埠行為。
2. 所謂鋰電池底板是否真的同時包含充電、保護及 5 V 升壓。
3. 最終外殼尺寸與鏡頭／螢幕相對位置。
4. 目標手機熱點的 2.4 GHz 相容性、省電斷線與長時間穩定性。
5. 配對碼顯示方式與未領取草稿 24 小時清理的實機體驗。
7. `tiger-camera.fengyenchia.com` 的 DNS、Vercel 部署、Cloudflare R2、Neon PostgreSQL 與登入提供者。
