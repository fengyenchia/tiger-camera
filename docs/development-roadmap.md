## W0：Web 收尾

2026-08-24 Android Chrome 實機功能流程已通過。iPhone Safari 不阻擋 P0，移入 R0 發布前跨平台檢查。

- 部署目前 Frontend 與 Backend；公開照片卡片外側保留一個下載按鈕。
- `GET /api/photos/:id/image?download=1` 必須回 `200 image/jpeg` 與 attachment，不開啟圖片頁面。
- iOS Safari 與 Android Chrome 可領取、後製及下載直式／橫式 JPEG。
- 拍立得框、日期、文字、濾鏡與基本調整可任意開關。
- 公開後自動進入相簿，照片可以 overlay 放大。
- 未公開草稿不能出現在公開 API；只有管理員 Bearer token 能永久刪除。
- 完成圖與資料庫 metadata 成功後才顯示保存成功。

詳細執行順序與記錄表見 [`w0-i0-guide.md`](w0-i0-guide.md)。

## I0：NFC

把被動 NFC 寫成固定 URL：

`https://tiger-camera.fengyenchia.com/create`

NFC 不保存領取碼或照片網址。驗收不同手機在鎖定／解鎖狀態下的掃描位置、距離與瀏覽器開啟結果，並在機身上保留手動輸入網址的備援說明。

2026-08-24 Android Chrome 已確認 NFC 可開啟固定 `/create` 並完成領取流程。尚未提供重複 10 次與 iPhone 的量化紀錄，列入 R0，不阻擋 P0。

## P0：鋰電池與升壓模組

> **狀態：已通過。** 2026-08-28 使用者確認 P0 整體實作與整理完成，包含 P0.1 電壓／估算百分比顯示。

預定架構：

`單節 3.7V LiPo（帶保護） → 充電／保護／5V 升壓模組 → 實體電源開關 → 主板 5V/GND`

實作順序：

1. 收貨後記錄電池尺寸、接頭、正負極與 datasheet；確認模組 BAT、5V OUT 與充電輸入口標示。
2. 不接主板，先量模組輸出極性及空載電壓，目標約 5.0–5.15V。
3. 接假負載／USB 電流表驗證負載壓降與溫升；不得直接相信賣場的 2.4A 峰值。
4. 關閉主板 USB-C，只以升壓輸出經開關供應主板 `5V/GND`；所有模組共地。
5. 反覆測試開機、預覽、拍照、Wi-Fi TLS 上傳，觀察 brownout、重啟、畫面閃爍與溫度。
6. 測試低壓保護、充電指示、關機充電與實際續航。未確認 power-path 前，充電時關閉相機。
7. 完成 30 次拍照／上傳循環及至少一次完整續航後，才鎖定外殼電池艙。

P0 通過條件：上傳峰值時 5V 軌不造成 brownout，模組與電池無異常發熱或膨脹；電源、充電與低壓保護可安全使用，並寫下實測續航與溫升。

## E0：外殼

只有在 P0 完成且實物量測齊全後才建模。V1 使用基本矩形相機造型，保留鏡頭、直式螢幕、快門、USB／充電口、開關、NFC 與天線淨空；不做老虎外觀或喇叭。

## R0：發布前強化

- iPhone Safari 跑一次 W0／I0 完整流程。
- 30 次完整拍照上傳、5 次 Wi-Fi 中斷恢復。
- 輪替 `DEVICE_UPLOAD_TOKEN` 後，舊 token 不得建立或完成草稿。
- 草稿逾期、發布與刪除後，Neon/R2 狀態一致且私人原圖被清除。
- 對外只保留必要 CORS origin，秘密不進入瀏覽器、韌體或 Git。
- Web lint、typecheck、測試與 production build 通過。
