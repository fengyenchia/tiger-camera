# 開發路線與里程碑

## 原則

- 先驗證最危險的整合，再做完整功能。
- 每一階段都有可判定的完成條件。
- 外殼在電子尺寸、熱與 RF 實測後才精修。
- GIF 留在 V1 完成後。

## 建議 8 階段

實際可依課業拆成 8～12 週；以下以「每階段完成再前進」為主，不強迫每週交付。

### Phase 0：採購與基準確認

任務：

- 購買核心驗證零件。
- 記錄收到的 XIAO、Sense 擴充板與相機型號／版號。
- microSD 格式化 FAT32。
- 建立 PlatformIO 空專案並跑官方相機、SD、螢幕範例。

完成條件：

- 三個官方範例可各自運作。
- 腳位與板版差異已寫回文件。

### Phase 1：核心硬體風險驗證

任務：

- 相機取景顯示到 ST7789。
- 拍照存至 microSD。
- 同一輪操作重複 30 次。
- 驗證 SPI transaction、CS 與時脈。

完成條件：

- 30 次循環無檔案損壞、花屏或重啟。
- 若失敗，已選定共用 SPI／軟體 SPI／硬體調整之一。

### Phase 2：拍照最小可用品

任務：

- 快門 debounce 與狀態機。
- 檔名、temp 寫入、JSON 中繼資料。
- 拍後回看與 5 句隨機成功文字；避免連續重複。
- 無 SD、SD 滿與相機失敗 UI。

完成條件：

- 重新開機後可讀回照片。
- 連拍 100 張測試成功率達 98% 以上。

### Phase 3：拍照回饋與電源

任務：

- 成功儲存後在回看照片疊加隨機小虎文字。
- `ROAR!`、`抓到你了！`、`虎視眈眈！`、`今日獵物 +1`、`小虎拍到了！` 五句皆可顯示，且不連續重複。
- 電池、USB-C 充電與 ADC 校正。
- 低電量、充電中、充飽畫面。

完成條件：

- 預覽、拍照、寫入與回看切換時不 brownout。
- 成功文字只在 JPEG 與 JSON 都寫入完成後顯示；失敗不誤報成功。
- 電量估計與萬用電表在可接受範圍。

### Phase 4：Wi‑Fi 區域網站

任務：

- AP、WPA2、DNS、mDNS、Captive Portal。
- 靜態網站與 `/api/v1`。
- 最新照片、分頁相簿、原圖下載。
- 手機同步時間。

完成條件：

- iPhone 與 Android 各至少一台可連線、開站、下載。
- 連續下載 20 張不重啟。

### Phase 5：手機高品質後製

任務：

- Canvas pipeline。
- 四款效果。
- 日期開關、原圖／完成圖下載。
- EXIF 方向與大圖記憶體處理。

完成條件：

- 三類瀏覽器輸出正確。
- 不會誤覆寫原圖。
- 首次使用者可在 2 分鐘完成流程。

### Phase 6：外殼與整合

任務：

- 尺寸定位板與功能殼。
- 虎嘴遮罩、鏡頭、快門、天線、USB-C。
- 線材固定、拆裝與電池保護。
- 角色動畫與視覺細節。

完成條件：

- 手持不遮關鍵元件。
- 裝置可拆修。
- 殼內 Wi‑Fi、文字可讀性與溫度仍合格。

### Phase 7：展示版穩定化

任務：

- 100 張耐久測試。
- SD 滿、斷電、低電量與多手機情境。
- 展示前清空／重設流程。
- 使用說明與已知限制。

完成條件：

- 全部 V1 驗收項目通過。
- 已知問題有 workaround，重大問題為 0。

## 決策關卡

| Gate | 問題 | 不通過的動作 |
|---|---|---|
| G0 | 相機＋SD＋TFT 可共存？ | 降時脈、軟體 SPI、重排腳位 |
| G1 | 拍照寫入與回看切換會重啟？ | 降背光峰值、改善供電、檢查狀態切換 |
| G2 | 網站能在 iOS／Android 進入？ | 調整 captive portal、強化 IP 備援 |
| G3 | 800 mAh 續航夠？ | 深睡、降亮度或換 1000 mAh |
| G4 | 殼內 Wi‑Fi／文字可讀性合格？ | 移天線、調整虎嘴遮罩與文字安全區 |

## GIF 待做規格

V1 通過後才進行：

- 長按快門：2～3 秒。
- 5～8 FPS。
- 12～20 張低解析度 JPEG。
- 另拍／選一張較高解析度封面 JPEG。
- ESP32 只存 frames 與 metadata。
- 手機端合成 240 × 240 或 320 × 240 GIF。
- 必須保留靜態 JPEG 下載。

在 GIF 完成前，長按快門可不分配功能，或顯示「動態模式尚未開放」，避免誤觸發拍照。
